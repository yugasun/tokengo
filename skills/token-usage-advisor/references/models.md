# Model and effort guidance

Use the local `catalog` command for currently available models and supported
effort levels. Historical records keep the model and effort actually used;
current defaults never rewrite them.

Do not infer a permanent capability ranking from model names. Choose one
candidate configuration from the task's scope, uncertainty, error cost, and
acceptance criteria. Preserve an explicit user preference when it is supported.

Recommend a lighter configuration as an experiment unless comparable successful
history exists. Escalate when validation fails, hidden dependencies appear,
the root cause is unknown, or the cost of a wrong answer is high. If a vendor's
current capability or supported effort matters, check its current official
documentation and record the verification date.
